Data on AWS

Step 2 connects data. A serverless API on AWS serves telemetry and operations in the twin's own metric frame, so any renderer can pin values to the right place.

The deployed API

EndpointReturns
GET /telemetryFreezer, cooler, kitchen and dry-storage temperature and humidity, door state, alarms, forklift positions
GET /operationsKPIs, areas with stock and utilisation, inventory by product family, supply-chain flows, community kitchen batches, trucks
GET /healthLiveness

Region us-east-2 (Ohio), deployed with scripts/deploy.sh from template.yaml (AWS SAM) on 2026-10-25. The account's organisation policy blocks Lambda, CloudFormation and API Gateway in us-east-1 and us-west-2, which is why it runs in Ohio. Measured: 1,000 sequential calls all succeeded, 67 ms median and 78 ms 95th-percentile round trip from a US cloud container.

The data is simulated. Values are computed from the clock, so the Lambda needs no database and two callers in the same second see the same numbers. Every payload carries simulated: true. The browser carries a line-for-line port of the simulator, kept in sync by tests, and uses it when the API is unreachable.

Operations layer

A food bank is a warehouse that runs in reverse: donations, USDA commodities and purchases arrive at the docks, volunteers sort rescued food, pallets go into dry racking, the cooler and the freezer, the community kitchen turns some of it into meals, and partner agencies collect the rest. The operations model follows one simulated day of that flow. Annual volumes, agency counts and floor area are published figures; shares, capacities and recipes are estimates flagged est: true in src/telemetry/operations.json. See the operations page and docs/OPERATIONS.md.
