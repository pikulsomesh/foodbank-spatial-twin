Browser (live)

The demo runs on any laptop or phone with no install: three.js shows the Blender facility, badges are pinned to telemetry positions, the forklift follows its live path, and Spark renders the splat captures (?captures, or photoreal.html to compare zones from their source cameras). It is published from public/ by GitHub Actions and reads the AWS API through the repository variable TWIN_API_URL. URL options: ?view=cold|aisle|sorting|market|kitchen, ?tour=1, ?sim=1. Reference: docs/VIEWER.md.

NVIDIA Omniverse on an AWS GPU Rendered

Omniverse RTX renders USD particle fields natively and path-traces them. The trial runs one EC2 g6.xlarge (NVIDIA L4) in us-east-2 with Omniverse Kit headless from NVIDIA's Isaac Sim container, opens twin.usda, renders fixed cameras, saves the images and terminates itself. A new AWS account starts with 0 GPU vCPU quota; 4 vCPUs were granted on 2026-10-25. For regular use the same image runs as an ECS service or AWS Batch job on a GPU Auto Scaling group with a minimum of zero, so an instance exists only while someone is rendering. A Kit extension that polls /telemetry and /operations sets attributes on the USD prims by id.

Facility rendered; splats not yet. Six runs on a real g6.xlarge in us-east-2 on 2026-10-25 took about 72 instance-minutes, about $0.97 at list price, and each instance terminated afterwards. Isaac Sim 5.1 crashed on the Deep Learning AMI's driver 595, started on plain Ubuntu with driver 580, and on run 6 rendered the facility in RTX (96 frames at 1280×720 in 17 to 46 s once warm). The Gaussian-splat captures loaded but rendered blank grey, so Omniverse rendering of splats is not shown. What failed, what fixed it and a working recipe: Omniverse learnings and pitfalls.

Blender

Blender 5.2 opens the facility directly, and scripts/blender_render_twin.py brings the splat captures in as point clouds (Blender's USD importer does not read ParticleField3DGaussianSplat yet). scripts/render_usd_splats.py renders true Gaussian splats from the USD on a plain CPU. Both read the same camera list, so stills line up shot for shot.

Reference: docs/RENDERING.md.
